# 캠퍼스 보행 그래프 데이터 수집 가이드

FR-07 장소 추천에 쓰는 서산캠퍼스 데이터를 모으는 방법이다.

> **지금 상태 (11/25):** `data/buildings.csv`의 좌표는 학교 항공사진의 건물 배치로 만든 **임시값**이다. 건물끼리의 상대 위치는 비슷하지만 실제 GPS와는 맞지 않으므로, 휴대폰 GPS로 "이동 가능"을 누르면 엉뚱한 건물이 나올 수 있다. 시연 모드(건물 선택)는 지금도 동작한다. 실측 좌표로 `lat`, `lng` 칸만 바꾸고 서버를 다시 켜면 DB도 바뀐다.

## 한눈에 보기

1. 엑셀 양식 [`data/templates/campus_graph_template.xlsx`](../data/templates/campus_graph_template.xlsx)를 받는다. 탭 4개: 사용법, buildings, path\_nodes, path\_edges
2. 캠퍼스 지도에 점과 선을 그린다 (아래 0번)
3. 엑셀 탭 3개를 채운다. 좌표는 구글 지도, 도보 시간은 네이버 지도 앱
4. 탭마다 **CSV UTF-8**로 저장해서 `data/` 폴더에 넣고 깃에 올린다 (아래 5번). 어려우면 엑셀 파일 그대로 백엔드 담당에게 넘긴다

| 탭 = 파일 | 한 행 | 예상 행 수 | 꼭 조사할 것 |
| --- | --- | --- | --- |
| buildings | 건물 1개 | 16 + 기타 | 이름, 중앙 좌표 |
| path\_nodes | 출입구 또는 길 교차점 1개 | 40\~60 | 좌표 (고도는 3\~5개만) |
| path\_edges | 두 노드를 잇는 길 1개 | 60\~90 | 양방향 도보 시간 |

엑셀에서 노란 머리글은 필수, 남색 머리글은 선택이다. 머리글에 마우스를 올리면 설명이 나오고, node\_type·edge\_type·노드 코드는 드롭다운으로 고른다.

## 0. 캠퍼스 지도에 그리기

캠퍼스 지도를 캡처하거나 인쇄해서 먼저 표시한다.

1. 건물마다 실제로 드나드는 출입구에 점 (●) → ENTRANCE 노드
2. 길이 갈라지거나 만나는 곳, 계단 위·아래에 점 (○) → JUNCTION 노드
3. 점과 점을 잇는 실제 길에 선 → 간선. 계단은 다른 색

점마다 이름(node\_code)을 붙여 지도에 적어 두면 엑셀 채우기가 쉽다. 출입구는 `E-건물코드-번호`(예: `E-INMUN-1`), 교차점은 `J-번호`(예: `J-07`).

**노드 규칙**

- 기타를 뺀 모든 건물에 출입구를 최소 1개. 정문·후문처럼 방향이 다르면 모두 찍는다 (서버가 가장 빨리 닿는 쪽을 쓴다)
- 곧은 길이라도 100m가 넘으면 중간에 하나 더
- 정문, 기숙사 입구처럼 사람이 처음 서 있기 쉬운 곳에도 하나 (GPS 위치를 가장 가까운 노드에 맞추기 때문)

## 1. 좌표 (lat, lng)

국내에서는 구글 지도가 좌표를 보여주지 않으므로 아래 방법을 쓴다.

- **PC (OpenStreetMap):** [openstreetmap.org](https://www.openstreetmap.org)에서 캠퍼스를 확대하고 위치를 오른쪽 클릭 → **"여기에 무엇이 있나요?"** 를 누르면 왼쪽 위에 `36.xxxxx, 126.xxxxx`가 나온다. 앞이 위도(lat), 뒤가 경도(lng). 화면 가운데 좌표는 주소창 `#map=18/36.xxxxx/126.xxxxx`에도 나온다.
- **휴대폰 (현장):** GPS 좌표 앱(앱스토어에서 "GPS 좌표" 검색)을 켜고 출입구 앞에 서서 숫자를 적는다. 위성 사진이 없는 OpenStreetMap보다 출입구 위치가 정확하다. 실내에서는 오차가 크니 밖에서 잰다.

## 2. 도보 시간 (forward\_seconds, backward\_seconds)

간선마다 네이버 지도 앱의 **도보 길찾기**로 from → to, to → from을 각각 검색해 **초**로 바꿔 넣는다 (2분 30초 → 150). 네이버 결과가 이상하거나 캠퍼스 안 길을 못 찾으면 직접 걸어서 스톱워치로 잰다. 계단은 실측을 권장한다.

두 칸을 비워 두면 서버가 좌표와 고도로 계산한다 (계산식은 `docs/ERD.md`).

## 3. 고도 (elevation\_m, 선택)

캠퍼스가 한쪽으로 꾸준히 높아지는 지형이라 모든 노드를 잴 필요는 없다. **가장 아래쪽(정문), 가운데, 가장 위쪽 노드 등 3\~5개만** 넣으면 서버가 나머지를 평면으로 추정한다. 네이버 도보 시간이 A→B와 B→A가 똑같이 나온다면(경사 미반영) 이 고도가 오르막을 반영하는 유일한 값이므로 꼭 넣는다.

구글 어스(웹 또는 Pro)에서 마우스를 올리면 오른쪽 아래에 고도가 나온다. 모두 같은 도구로 잰다.

## 4. 간선 규칙

- 한 길은 한 줄만 쓴다 (A→B를 썼으면 B→A 줄은 만들지 않는다. 반대 방향 시간은 backward\_seconds에)
- edge\_type: `PATH` 보행로, `ROAD` 차도 옆, `STAIRS` 계단, `INDOOR` 건물 안 통로 (1층으로 지나가면 빠른 경우 그 건물의 두 출입구를 잇는다)
- 실제로 걸을 수 있는 길만. 잔디밭 가로지르기, 공사 중인 길은 넣지 않는다
- 모든 출입구가 선을 따라 서로 닿아야 한다

## 5. 엑셀 → CSV로 저장해서 넣기

1. 엑셀에서 `buildings` 탭을 연 상태로 **파일 → 다른 이름으로 저장**
2. 파일 형식을 **CSV UTF-8(쉼표로 분리)(\*.csv)**로 고르고 이름을 `buildings.csv`로 저장. 그냥 "CSV"를 고르면 한글이 깨진다
3. "선택한 시트만 저장됩니다" 경고는 확인을 누른다. `path_nodes`, `path_edges` 탭도 같은 방법으로 저장 (엑셀은 지금 보는 탭만 저장한다)
4. CSV 3개를 백엔드 프로젝트의 `data/` 폴더에 넣는다 (`data/templates/`가 아니라 `data/` 바로 아래)
5. 깃에 커밋해서 올린다. 서버는 켤 때 이 파일들을 읽는다

구글 스프레드시트를 쓰면 **파일 → 다운로드 → 쉼표로 구분된 값(.csv)**으로 탭마다 받으면 된다 (한글 문제 없음).

## 6. 제출 전 확인

- [ ] buildings의 name이 프론트 건물 목록과 정확히 같다 (띄어쓰기, 괄호 포함)
- [ ] 기타를 뺀 모든 건물에 ENTRANCE가 1개 이상 있다
- [ ] node\_code, building\_code에 중복이 없다
- [ ] 같은 길이 거꾸로 두 번 들어가 있지 않다
- [ ] 좌표의 위도·경도 순서가 바뀌지 않았다 (위도는 36, 경도는 126으로 시작)
- [ ] 고도를 넣은 노드가 3개 이상이고, 아래쪽과 위쪽 끝이 들어 있다

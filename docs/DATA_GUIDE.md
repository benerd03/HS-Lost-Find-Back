# 캠퍼스 보행 그래프 데이터 수집 가이드

FR-07 장소 추천(C안)에 쓰는 서산캠퍼스 데이터를 모으는 방법이다. 결과물은 CSV 3개이고, 양식은 [`data/templates/`](../data/templates)에 예시 행과 함께 있다. 예시 행의 좌표와 고도는 형식 설명용 가짜 값이니 지우고 채운다.

| 파일 | 한 행 | 예상 행 수 |
| --- | --- | --- |
| `buildings.csv` | 건물 1개 | 16 + 기타 |
| `path_nodes.csv` | 출입구 또는 길 교차점 1개 | 40\~60 |
| `path_edges.csv` | 두 노드를 잇는 길 1개 (양방향) | 60\~90 |

예상 작업량은 두 사람이 지도로 반나절, 실측 보정까지 하면 하루다. 구글 스프레드시트에서 탭 3개로 같이 채우고, 탭마다 "파일 → 다운로드 → CSV"로 내려받아 `data/` 폴더에 같은 파일명으로 넣는다.

## 0. 준비: 캠퍼스 지도에 그리기

먼저 캠퍼스 지도를 캡처하거나 인쇄해서, 아래를 손으로 표시해 두면 빠르다.

1. 건물마다 실제로 드나드는 출입구에 점 (●)
2. 길이 갈라지거나 만나는 곳, 언덕 꼭대기·바닥, 계단 위·아래에 점 (○)
3. 점과 점을 잇는 실제 길에 선. 계단은 다른 색

이 그림이 그래프다. ●가 ENTRANCE 노드, ○가 JUNCTION 노드, 선이 간선이다.

## 1. buildings.csv

| 열 | 필수 | 규칙 |
| --- | --- | --- |
| building\_code | 예 | 영문 대문자·숫자·하이픈, 20자 이내, 중복 불가. 예: `INMUN`, `DORM1`. 다른 CSV에서 건물을 가리킬 때 쓴다 |
| name | 예 | 화면에 보이는 이름. 프론트 건물 목록(16개 + 기타)과 글자까지 똑같이 |
| lat, lng | 기타 외 예 | 건물 중앙 좌표, 소수 6자리. "기타"는 비운다 |
| sort\_order | 예 | 드롭다운 순서 (프론트 목록 순서) |
| memo | 아니오 | 자유 |

## 2. path\_nodes.csv

| 열 | 필수 | 규칙 |
| --- | --- | --- |
| node\_code | 예 | 출입구는 `E-건물코드-번호` (예: `E-INMUN-1`), 교차점은 `J-번호` (예: `J-07`). 중복 불가 |
| node\_type | 예 | `ENTRANCE` 또는 `JUNCTION` |
| building\_code | ENTRANCE만 | 출입구가 속한 건물. JUNCTION은 비운다 |
| lat, lng | 예 | 소수 6자리 (약 10cm 단위) |
| elevation\_m | 예 | 해발 고도(m), 소수 1자리. 아래 "고도 얻기" 참고 |
| memo | 아니오 | 어디인지 사람이 알아볼 설명. 예: 학생회관 앞 삼거리 |

**노드를 찍는 규칙**

- 추천 후보가 될 건물(기타 제외)은 출입구를 **최소 1개** 찍는다. 정문·후문처럼 방향이 다른 출입구가 있으면 모두 찍는다. 서버는 그중 가장 빨리 닿는 출입구를 쓴다.
- 길이 갈라지는 곳, 언덕 꼭대기와 바닥, 계단 위와 아래에는 반드시 JUNCTION을 둔다. 고도가 바뀌는 지점이 빠지면 오르막이 계산되지 않는다.
- 곧은 길이라도 100m가 넘으면 중간에 하나 더 둔다.
- 정문, 기숙사 입구처럼 사람들이 처음 위치하기 쉬운 곳에도 둔다 (GPS 위치를 가장 가까운 노드에 맞추기 때문).

## 3. path\_edges.csv

| 열 | 필수 | 규칙 |
| --- | --- | --- |
| from\_node\_code, to\_node\_code | 예 | 길의 양 끝 노드. **한 길은 한 행만** 쓴다 (A→B를 썼으면 B→A는 쓰지 않음). from은 아래쪽(고도 낮은 쪽)을 권장 |
| edge\_type | 예 | `PATH` 보행로, `ROAD` 차도 옆, `STAIRS` 계단, `INDOOR` 건물 안 통로 |
| distance\_m | 아니오 | 비우면 서버가 두 좌표로 계산한다. 길이 많이 휘어 직선과 다르면 실제 거리를 적는다 |
| forward\_seconds | 아니오 | from → to를 실제로 걸어 잰 초. 넣으면 계산값 대신 이 값을 쓴다 |
| backward\_seconds | 아니오 | to → from 실측 초 |
| memo | 아니오 | 예: 경사 심함, 비 오면 미끄러움 |

**간선 규칙**

- 실제로 걸어 다닐 수 있는 길만 잇는다. 잔디밭 가로지르기, 공사 중인 길은 넣지 않는다.
- 건물 안을 지나가면 더 빠른 경우(1층 통로)는 그 건물의 두 출입구를 `INDOOR`로 잇는다.
- 모든 출입구는 간선을 따라 다른 모든 출입구에 닿아야 한다. 끊긴 노드가 있으면 서버가 시작할 때 목록을 로그에 남긴다.

## 4. 좌표와 고도 얻기

**좌표 (lat, lng):** PC에서 구글 지도를 열고 위치를 오른쪽 클릭하면 맨 위에 `36.69xxxx, 126.58xxxx`가 보이고, 누르면 복사된다. 앞이 위도(lat), 뒤가 경도(lng)다. 위성 사진 모드로 보면 출입구 위치를 찾기 쉽다.

**고도 (elevation\_m):** 구글 어스(웹 또는 Pro)에서 마우스를 올리면 오른쪽 아래에 고도가 표시된다. 정확한 해발 값보다 **노드 사이의 높이 차이**가 중요하므로, 모든 노드를 같은 도구 하나로 잰다. 휴대폰 GPS 고도는 오차가 커서 쓰지 않는다. 기압 센서가 있는 휴대폰의 고도계 앱은 같은 날 한 번에 돌면서 재면 높이 차이가 비교적 정확하니, 지도 값이 이상할 때 확인용으로 쓴다.

## 5. 실측 보정 (시연 전)

1. 언덕이 있는 경로 2개, 평지 경로 1개를 골라 실제로 걸으며 스톱워치로 잰다. 올라갈 때와 내려올 때를 따로 잰다.
2. 관리자 API로 계산된 값과 비교한다 (명세서 "보행 그래프" 절의 `GET /api/admin/path-graph/route`).
3. 차이가 30% 이상이면 그 간선에 forward·backward\_seconds를 실측값으로 넣는다. 계단은 처음부터 실측값을 넣는 것을 권장한다.

## 6. 제출 전 확인

- [ ] buildings의 name이 프론트 건물 목록과 정확히 같다 (띄어쓰기, 괄호 포함)
- [ ] 기타를 뺀 모든 건물에 ENTRANCE가 1개 이상 있다
- [ ] node\_code, building\_code에 중복이 없다
- [ ] path\_edges에 같은 길이 거꾸로 두 번 들어가 있지 않다
- [ ] 좌표의 위도·경도 순서가 바뀌지 않았다 (서산캠퍼스는 위도 36, 경도 126으로 시작)
- [ ] 서버를 켰을 때 "연결되지 않은 노드" 경고가 없다
